# 🦒 경험을 먹고 자라는 기린

> 더 높이, 더 단단하게.  
> 튼튼한 기초 위에서 경험을 쌓고, 더 넓은 세계로 나아가는 개발자 포트폴리오.

프로젝트 경험을 먹이로 삼아 성장하는 기린을 통해 개발자로서의 역량과 성장 과정을 보여주는 인터랙티브 포트폴리오입니다.

방문자는 기린과 함께 길을 따라 이동하며 프로젝트 나무를 만나고, 가지에 달린 잎을 선택해 프로젝트를 살펴봅니다. 경험을 먹을 때마다 기린의 목이 길어지고, 더 높은 곳을 바라보게 됩니다.

---

## 1. 프로젝트 상태

현재는 초기 프로토타입을 바탕으로 게임형 메인 화면의 디자인을 구체화한 단계입니다.

이 문서의 디자인과 인터랙션은 앞으로 구현할 목표를 포함합니다. 실제 반영 여부는 소스 코드와 실행 화면을 기준으로 확인합니다.

### 기존 프로토타입 기반

- React + TypeScript + Vite
- 프로젝트 상세 콘텐츠
- 프로젝트 선택과 먹이 주기 상태 관리
- 동일 프로젝트의 중복 성장 방지
- SVG 기린과 성장 애니메이션 코드
- 성장 단계에 따른 풍경 변화 코드

### 이번에 확정한 개편 방향

- 별빛 픽셀아트 게임 스타일
- 데스크톱 중심의 넓은 횡스크롤 화면
- 작은 기린으로 시작하는 성장 여정
- 프로젝트 나무 네 그루와 가지에 매달린 먹이 잎
- 한 화면에 약 세 그루가 보이는 배치
- 먹기 → 목 성장 → 다음 나무로 이동하는 흐름
- 시작과 마지막에만 표시하는 다리의 기반 역량
- 마지막 장면에서 미래의 성장을 암시하는 높은 숲

## 2. 핵심 메시지와 상징

### 튼튼한 기초 위의 성장

기린의 신체와 주변 환경에 다음 의미를 담습니다.

| 요소 | 의미 |
|---|---|
| 튼튼한 네 다리 | 개발자로서의 기반 역량과 태도 |
| 프로젝트 나무 네 그루 | 실제 수행한 프로젝트 |
| 가지에 매달린 잎 | 프로젝트를 통해 얻은 경험 |
| 길어지는 목 | 경험을 통해 이룬 성장 |
| 먼 곳의 더 높은 숲 | 앞으로 배우고 도전할 수많은 경험 |
| 숲으로 이어지는 길 | 끝나지 않은 성장 여정 |

### 다리에 연결할 기반 역량

현재 디자인 문구 후보:

- Python
- 데이터 분석
- 연결·개선
- 열정

이 항목들은 나무나 땅속 지층이 아니라 기린의 다리에 연결해 표현합니다.

정확한 문구와 자격 정보는 추후 확정합니다. 자격명을 표기할 경우 실제 명칭과 취득·준비 상태를 확인합니다.

## 3. 디자인 방향

### 비주얼 스타일

- 2D 픽셀아트
- 깊은 남색 밤하늘
- 보라색 산과 먼 언덕
- 청록빛 풀밭과 흙길
- 황금빛 기린, 별, 반딧불이
- 픽셀 스타일의 제목과 버튼
- 프로젝트 본문은 읽기 편한 글꼴 사용

### 데스크톱 우선

모바일 화면을 늘리는 방식이 아니라 넓은 데스크톱 화면을 기준으로 구성합니다.

- 수평으로 이어지는 길과 풍경을 충분히 확보합니다.
- 시작 기린은 화면을 크게 차지하지 않도록 작게 배치합니다.
- 성장 전후의 크기 차이가 분명하게 느껴지도록 합니다.
- 성장 후에도 머리와 발이 화면 안에 보이도록 카메라를 조정합니다.
- 모바일 대응은 데스크톱 구성을 확정한 뒤 별도로 설계합니다.

### 배경 나무 사용 원칙

일반 탐험 구간에는 프로젝트 나무와 혼동되는 장식용 배경 나무를 배치하지 않습니다.

배경의 깊이는 다음 요소로 표현합니다.

- 산과 낮은 언덕
- 별과 구름
- 안개
- 풀과 작은 바위
- 반딧불이

마지막 장면에서만 미래를 상징하는 많은 나무의 숲을 보여줍니다.

## 4. 사용자 흐름

```text
시작 화면
→ ‘기린 키우기 시작’
→ 기린이 오른쪽으로 이동
→ 현재 프로젝트 나무 앞에서 정지
→ 가지의 잎 클릭
→ 프로젝트 상세 확인
→ ‘이 경험으로 먹이 주기’
→ 잎 먹기
→ 목 성장 시작
→ 오른쪽으로 걸으며 성장 마무리
→ 다음 프로젝트 나무에 도착
→ 네 프로젝트 경험 완료
→ 더 높은 미래의 숲을 바라보는 장면
```

이동은 기본적으로 자동으로 진행합니다.

방문자가 방향키를 계속 조작하는 게임보다, 프로젝트를 읽고 경험을 선택하는 흐름에 집중합니다.

## 5. 화면 구성

### 5.1 시작 화면

표시 문구:

> 경험을 먹고 자라는 기린  
> 더 높이, 더 단단하게.

주요 요소:

- ‘기린 키우기 시작’ 버튼
- 작고 목이 짧은 기린
- 앞으로 이어지는 길
- 점점 높아지는 프로젝트 나무
- 기린의 네 다리에 연결된 기반 역량 설명

시작 버튼을 누르면 제목, 버튼, 다리 설명이 사라지고 같은 세계 안에서 기린이 걷기 시작합니다.

### 5.2 탐험 화면

- 기린은 오른쪽으로 이동합니다.
- 카메라는 기린을 따라갑니다.
- 한 화면에 프로젝트 나무가 약 세 그루 보이게 합니다.
- 이동하면 지나온 나무가 왼쪽으로 빠지고 다음 나무가 오른쪽에서 등장합니다.
- 일반 플레이 중에는 다리 설명을 표시하지 않습니다.

### 5.3 프로젝트 상세

현재 나무의 잎을 클릭하면 경험 기록창을 엽니다.

포함할 정보:

- 프로젝트 이름과 개요
- 수행한 역할
- 해결한 문제
- 배운 점과 성장한 역량
- 프로젝트 이미지
- GitHub 및 관련 링크
- ‘이 경험으로 먹이 주기’ 버튼

상세를 닫으면 해당 나무 앞에서 대기하는 상태로 돌아옵니다.

### 5.4 마지막 장면

네 번째 경험 이후에도 길은 끝나지 않습니다.

- 성장한 기린이 오른쪽의 먼 숲을 바라봅니다.
- 다리의 기반 역량 설명이 다시 나타납니다.
- 먼 곳에는 현재 기린보다 더 높은 나무들이 많이 보입니다.
- 숲에는 프로젝트 번호, 이름, 클릭 버튼을 붙이지 않습니다.
- 길은 숲 안으로 계속 이어집니다.

표시 문구:

> 단단히 딛고, 더 높은 곳으로.  
> 아직 만나지 않은 경험들이 기다리고 있습니다.

버튼:

- 프로젝트 다시 보기
- GitHub
- 연락하기

‘성장 완료’나 ‘모든 여정 종료’라는 표현은 사용하지 않습니다.

## 6. 프로젝트 나무

나무는 기반 역량이 아니라 실제 프로젝트를 나타냅니다.

| 순서 | 프로젝트 | 주요 경험 |
|---|---|---|
| 01 | 홈페이지 클론 | 직접 구현, 반응형 화면, JavaScript 기능 |
| 02 | 백엔드·DB·배포 | Flask 백엔드, DB 연동, Docker 배포 |
| 03 | YOLO 프로젝트 | 데이터 수집, 라벨링, 학습과 재학습 |
| 04 | RAG·LLM 챗봇 | 응답 설계, 데이터 저장·조회, 프론트·백엔드 연결 |

첫 프로젝트 저장소:

https://github.com/girint/firsrt_project

### 콘텐츠 작성 원칙

- 실제 수행한 작업과 기여만 기재합니다.
- 확인하지 않은 기술, 수치, 성과를 추가하지 않습니다.
- 프로젝트 설명은 기능 나열보다 문제 해결과 성장에 집중합니다.
- 세부 구현은 README와 GitHub로 연결합니다.
- YOLO 프로젝트는 아동학대 여부를 최종 판단하는 시스템처럼 표현하지 않습니다.
- DB 종류, 라이브러리, RAG 구성 등은 실제 자료로 확인합니다.

### 나무와 먹이의 형태

- 첫 나무는 작고 잎의 위치가 낮습니다.
- 다음 나무로 갈수록 나무와 먹이 잎의 높이가 올라갑니다.
- 잎은 바닥이 아니라 가지에 매달려 있습니다.
- 나무의 높이뿐 아니라 가지와 수관 모양도 다르게 표현합니다.
- 현재 먹을 수 있는 잎은 빛과 선택 표시로 구분합니다.

## 7. 애니메이션 계획

### 대기

- 기린의 호흡
- 눈 깜빡임
- 귀와 꼬리 움직임
- 풀의 흔들림
- 별과 반딧불이의 움직임

### 이동

- 다리의 걷기 동작
- 발이 닿을 때 작은 먼지나 풀잎 반응
- 배경 레이어별 이동
- 기린을 따라가는 카메라

### 먹기와 성장

```text
기린이 가지의 잎으로 고개를 뻗음
→ 잎을 먹음
→ 작은 빛 입자 발생
→ 목이 부드럽게 길어지기 시작
→ 걸음을 떼며 성장 마무리
→ 다음 나무 앞에서 정지
```

목이 길어질 때 기린 전체 이미지를 세로로 늘리지 않습니다. 머리, 몸통, 다리의 형태를 유지하면서 목 부분이 성장하도록 설계합니다.

성장 중에는 몸과 발의 안정감을 유지합니다.

## 8. 상태 관리 원칙

- 같은 프로젝트로 두 번 성장하지 않습니다.
- 먹기·성장·이동 중에는 중복 동작을 막습니다.
- 완료한 프로젝트도 다시 읽을 수 있게 합니다.
- 현재 나무, 완료한 프로젝트, 성장 단계가 서로 일치하도록 관리합니다.
- 다음 나무가 보이더라도 기본 진행은 순서대로 유지합니다.
- 아직 닿을 수 없는 잎에는 짧은 안내를 표시합니다.

안내 문구 예시:

> 조금 더 자라면 닿을 수 있어요.

향후 진행 상태 저장과 새로고침 복원을 추가합니다.

## 9. 기술 및 파일 구조

### 현재 기반

- React
- TypeScript
- Vite
- CSS
- SVG
- requestAnimationFrame

픽셀아트 에셋 제작 방식과 추가 애니메이션 라이브러리는 아직 확정하지 않았습니다.

### 주요 파일

```text
src/
├─ App.tsx
├─ App.css
├─ index.css
├─ main.tsx
└─ assets/
```

| 파일 | 역할 |
|---|---|
| App.tsx | 프로젝트 데이터, 상태, 화면과 상호작용 |
| App.css | 메인·상세 레이아웃과 화면별 스타일 |
| index.css | 전역 스타일 |
| main.tsx | 앱 진입점 |
| assets/ | 이미지 및 시각 에셋 |

개편 시 기존 프로젝트 콘텐츠와 상태 로직을 최대한 유지합니다.

필요한 부분부터 컴포넌트를 분리하고, 전체 코드를 불필요하게 다시 작성하지 않습니다.

## 10. 로컬 실행

프로젝트 루트에서 실행합니다.

```bash
npm install
npm run dev
```

개발 서버 종료:

```text
Ctrl + C
```

Windows PowerShell에서 npm 실행 정책 문제가 발생하면 Git Bash를 사용하거나 다음 명령을 사용합니다.

```powershell
npm.cmd run dev
```

초기 의존성 충돌 대응 과정에서 TypeScript 5.9.3을 사용했습니다. 현재 버전 정보는 package.json과 잠금 파일을 기준으로 확인합니다.
